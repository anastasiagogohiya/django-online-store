# Документация сценариев пользовательского модуля (Gherkin)

## Общее описание

Модуль отвечает за аутентификацию, управление профилем, смену пароля и загрузку аватара.  
Ниже приведены сценарии поведения для каждого API-эндпоинта.

---

## 1. Регистрация пользователя  
**Эндпоинт:** `POST /sign-up`  
**Тело:** `{ "username": string, "password": string, "fullName": string }`

### Сценарий: Успешная регистрация
```gherkin
Дано: пользователь не зарегистрирован в системе
Когда: отправлен запрос на /sign-up с валидными username, password, fullName
Тогда: возвращается статус 200
И: в базе данных создаётся пользователь с указанным username
И: создаётся профиль с указанным fullName
```

### Сценарий: Ошибка при регистрации с занятым username
```gherkin
Дано: в системе уже есть пользователь с username "jenn"
Когда: отправлен запрос на /sign-up с username "jenn" и любыми паролем/полным именем
Тогда: возвращается статус 400
И: сообщение об ошибке указывает на дубликат
```

### Сценарий: Ошибка при отсутствии обязательных полей
```gherkin
Дано: отправлен запрос на /sign-up
Когда: одно из полей (username, password, fullName) отсутствует или пустое
Тогда: возвращается статус 400
И: в ответе содержится описание ошибки валидации
```

---

## 2. Вход пользователя  
**Эндпоинт:** `POST /sign-in`  
**Тело:** `{ "username": string, "password": string }`

### Сценарий: Успешный вход
```gherkin
Дано: пользователь с username "jenn" и паролем "jenn" зарегистрирован
Когда: отправлен запрос на /sign-in с корректными username и password
Тогда: возвращается статус 200
И: в ответе присутствует токен авторизации
```

### Сценарий: Ошибка входа при неверном пароле
```gherkin
Дано: пользователь с username "jenn" зарегистрирован
Когда: отправлен запрос на /sign-in с верным username, но неверным паролем
Тогда: возвращается статус 401
И: сообщение об ошибке "Неверные учетные данные"
```

### Сценарий: Ошибка входа при несуществующем пользователе
```gherkin
Дано: пользователь с username "jenn" не существует
Когда: отправлен запрос на /sign-in с несуществующим username
Тогда: возвращается статус 401
И: сообщение об ошибке "Неверные учетные данные"
```

---

## 3. Выход пользователя  
**Эндпоинт:** `POST /sign-out`  
**Требуется:** токен авторизации в заголовке

### Сценарий: Успешный выход
```gherkin
Дано: пользователь авторизован (имеет валидный токен)
Когда: отправлен запрос на /sign-out с токеном
Тогда: возвращается статус 200
И: токен пользователя удаляется из базы данных
```

---

## 4. Получение профиля  
**Эндпоинт:** `GET /profile`  
**Требуется:** токен авторизации

### Сценарий: Получение данных профиля авторизованного пользователя
```gherkin
Дано: пользователь авторизован
Когда: отправлен GET-запрос на /profile
Тогда: возвращается статус 200
И: в ответе содержатся все поля профиля (email, phone, fullName, avatar и т.д.)
```

---

## 5. Обновление профиля  
**Эндпоинт:** `POST /profile`  
**Тело:** `{ "email": string (опционально), "phone": string (опционально) }`  
**Требуется:** токен авторизации

### Сценарий: Успешное обновление email и телефона
```gherkin
Дано: авторизованный пользователь
Когда: отправлен POST-запрос на /profile с валидными email и phone
Тогда: возвращается статус 200
И: в ответе отображаются обновлённые email и phone
И: в базе данных профиль обновлён
```

### Сценарий: Ошибка при невалидном email или телефоне
```gherkin
Дано: авторизованный пользователь
Когда: отправлен POST-запрос на /profile с некорректным email (не email-формат) или телефоном (не цифры)
Тогда: возвращается статус 400
И: в ответе содержится сообщение "Введите корректные данные"
И: поля не обновляются
```

### Сценарий: Ошибка при попытке установить телефон, занятый другим пользователем
```gherkin
Дано: в системе есть другой пользователь с телефоном "1234567890"
И: авторизованный пользователь пытается указать этот же номер
Когда: отправлен POST-запрос на /profile с phone "1234567890"
Тогда: возвращается статус 400
И: в ответе ошибка валидации поля "phone"
```

### Сценарий: Обновление собственным телефоном или email (без ошибки)
```gherkin
Дано: авторизованный пользователь уже имеет телефон "1111111111" и email "same@example.com"
Когда: отправлен POST-запрос на /profile с такими же значениями phone и email
Тогда: возвращается статус 200
И: данные остаются прежними (без ошибки уникальности)
```

## 6. Смена пароля  
**Эндпоинт:** `POST /change-password`  
**Тело:** `{ "currentPassword": string, "newPassword": string }`  
**Требуется:** токен авторизации

### Сценарий: Успешная смена пароля
```gherkin
Дано: авторизованный пользователь знает текущий пароль
Когда: отправлен POST-запрос на /change-password с корректным currentPassword и newPassword
Тогда: возвращается статус 200
И: сообщение "Вы успешно поменяли пароль"
И: в базе данных пароль обновлён на новый
```

### Сценарий: Ошибка при неверном текущем пароле
```gherkin
Дано: авторизованный пользователь
Когда: отправлен POST-запрос на /change-password с неверным currentPassword
Тогда: возвращается статус 400
И: сообщение "Вы ввели неправильный текущий пароль"
И: пароль не изменяется
```

### Сценарий: Ошибка при отсутствии одного из полей
```gherkin
Дано: авторизованный пользователь
Когда: отправлен POST-запрос на /change-password без currentPassword или без newPassword
Тогда: возвращается статус 400
И: сообщение "Текущий и новый пароль обязательны"
```

---

## 7. Загрузка аватара  
**Эндпоинт:** `POST /change-avatar`  
**Тело:** `multipart/form-data` с полем `avatar` (файл) и опционально `alt`  
**Требуется:** токен авторизации

### Сценарий: Успешная загрузка валидного изображения
```gherkin
Дано: авторизованный пользователь
Когда: отправлен запрос на /change-avatar с файлом типа PNG, JPEG или GIF
Тогда: возвращается статус 200
И: аватар сохраняется, ссылка на него появляется в профиле
```

### Сценарий: Ошибка при отсутствии файла
```gherkin
Дано: авторизованный пользователь
Когда: отправлен запрос на /change-avatar без поля avatar (только alt)
Тогда: возвращается статус 400
И: в ответе ошибка "avatar" (поле обязательно)
```

### Сценарий: Ошибка при загрузке не-изображения
```gherkin
Дано: авторизованный пользователь
Когда: отправлен запрос на /change-avatar с файлом, который не является изображением (текстовый файл, битый JPEG, BMP)
Тогда: возвращается статус 400
И: в ответе ошибка валидации поля "avatar" (неверный формат)
```
